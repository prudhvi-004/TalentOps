AI Notes & Task Bar

How TalentOps reads the notes written by the Sense AI user in JobDiva, shows them on each job, and turns missed follow-ups into automated tasks.

Overview Files changed 1. Display logic 2. Audit & tasks API endpoints Front end Speed & rate limits Settings & storage How to test Limits & to-do

Overview

The Sense AI system talks to candidates and, after each conversation, drops a note on the candidate's record in JobDiva. TalentOps now does two things with those notes:

1. Display

On a job's detail page, AI-evaluated people appear under Engaged Applicants or Engaged Candidates, with a green / red / orange colour band.

2. Audit & tasks

If no recruiter follows up (a REC_AI note) within 120 minutes, an automated task is created for the job's primary recruiter. It closes itself once a follow-up note exists.

1. Display logic

Implemented in ai-notes.service.js — classify() (line 95) and buildItems() (line 108).

Step 1 — is it an AI note we care about?

A note is used only if both are true:

  • It was written by the AI user: RECRUITERID equals 1453881 (or RECRUITERNAME is "Sense Messaging").
  • Its TYPENAME is one of the four known types below.

Anything else is ignored.

TYPENAME in JobDivaSection on the job pageColour
Sense AI Auto sourcing Evaluation: PositiveEngaged Candidatesgreen
Sense AI Auto sourcing Evaluation: NegativeEngaged Candidatesred
Sense AI Applicant Review: PositiveEngaged Applicantsgreen
Sense AI Applicant Review: NegativeEngaged Applicantsred

Step 2 — one entry per candidate

  • All AI notes for a candidate are grouped; the most recent note decides the section and the green/red colour.
  • If the candidate has AI notes in both sections, the band becomes orange and a ⚠ marker is shown (flag for attention). The most recent note still decides which section they are listed in.
  • The score is read from the note text ("Score on evaluation: 8" or "AI Conviction score: 3").

Step 3 — what each entry contains

{
  id: "6203827265891",            // candidate id from the note
  jobId: "29424659",
  name: "Ileana Martinez",
  aiCategory: "Candidate",        // or "Applicant"
  sentiment: "positive",          // or "negative"
  band: "green",                  // green | red | orange
  flagged: false,                 // true = in both sections
  aiStageLabel: "Sense AI Auto sourcing Evaluation: Positive",
  score: 8,
  aiNoteAt: "2026-10-07T22:53:57.000Z",   // starts the 120-minute clock
  responded: false,               // a REC_AI note exists after aiNoteAt
  respondedAt: null
}

Opening a candidate

Clicking a candidate opens the profile using the Candidate ID from the note. The profile is fetched from JobDiva by the existing candidate lookup (getCandidateById), so notes, resume and actions work as they do for any other candidate.

Timestamps. DATECREATED comes without a timezone (e.g. 2026-10-08T12:31:57). In your sample, ACTIONDATE is exactly 4 hours later, so I treat it as US Eastern time and convert (parseNoteDate(), line 81). If your account is in another zone, set JOBDIVA_NOTE_TIMEZONE.

2. Audit & task bar logic

Implemented in reconcileTasks() (line 163) and buildItems().

The rule in one sentence

After an AI note, if nobody drops a REC_AI note on the same candidate and same job within 120 minutes, create one task for the job's primary recruiter.

12:31:57 — AI note lands on John Cena / Job 9921. The clock starts from the note's own DATECREATED (not from when TalentOps first saw it).
13:31:57 — Hourly refresh runs. No REC_AI note yet; still inside the window, so nothing happens.
14:31:57 — 120 minutes passed with no follow-up. The next refresh creates the task: "Review AI Evaluated Candidate — John Cena".
later — A recruiter drops a REC_AI note. The next refresh marks the candidate responded (✍️ shown) and the task becomes completed automatically.

The five rules, and where each lives

RuleHow it is done
1. No recruiter filter on the follow-upAny note with TYPENAME = REC_AI on the same candidate and job, created after the AI note, counts. We do not check who wrote it.
2. The 120 minutes start at the AI note's timeaiNoteAt comes from the note's DATECREATED in JobDiva.
3. One task per candidate per jobTask id is ai-<jobId>-<candidateId>-<aiNoteId>. Same note never creates a second task. A newer AI note has a new id, so the clock restarts and a new task is possible.
4. Task closes itselfWhen the refresh finds a REC_AI note after the AI note, status becomes completed with a completion time.
5. The ✍️ indicator persistsIt is recomputed from the notes each refresh. Once a follow-up exists it stays; the first follow-up is the one recorded.

What a task looks like

{
  id: "ai-29424659-6579819323960-1247122150",
  type: "Automated",
  status: "pending",              // later "completed"
  jobId: "29424659",
  candidateId: "6579819323960",
  candidateName: "Atrinity Thomas",
  assigneeName: "V Mithra",       // job's primary recruiter
  priority: "High",               // High if AI said Positive, else Normal
  title: "Review AI Evaluated Candidate — Atrinity Thomas",
  detail: "AI evaluated this candidate at … No follow-up note has been recorded. Please review and drop a REC_AI note.",
  createdAt: "…", completedAt: null
}

Who gets the task

  • The owner is the job's primary recruiter, looked up by getJobAssignment() using JobDiva's JobDetail and JobsInternalUsersDetail.
  • pickPrimaryRecruiter() reads the PRIMARYRECRUITER="1" flag and FIRSTNAME/LASTNAME fields. (The earlier code looked for role/userName, which JobDiva does not send, so no recruiter was ever found.)
  • On GET /api/tasks, a recruiter sees only their own tasks; an admin sees all. Ownership matches on JobDiva id or name (see Limits).

When the check runs

  • On demand: opening a job page loads its AI notes. Cached results show instantly; if older than 5 minutes they refresh in the background (FRESH_MS).
  • Hourly: startHourlyPoll() (line 257) re-syncs every job that has been loaded before, so tasks appear and close even if nobody opens the page.
  • State is saved to data/runtime/ai-audit.json, so tasks survive restarts.

Speed & rate limits

Pages were very slow and JobDiva returned 429 Request Limit Exceeded. All of this is in ats.service.js.

ChangeEffect
Stale-while-revalidate cache (swr(), line 92)Once data is loaded it is shown instantly; if older than a few minutes it refreshes in the background.
Disk cache in data/runtime/cache/Server restarts start warm instead of re-fetching hundreds of jobs.
Concurrency cap (JOBDIVA_MAX_CONCURRENT, default 4)Stops bursts of parallel calls from tripping the rate limit.
Retry with back-off on 429Up to 6 retries, honouring JobDiva's Retry-After header.
Job list returns after core detailsContacts and recruiter names load in the background (enrichJobs()). First load dropped from ~86 s to ~31 s.
Candidates for a job fetched in batchesWas 2 calls per person; now one call per 150 / 25 people. 12 candidates: 22.8 s → 5.3 s, with identical results.
Job activity cachedThe recruiter-scope check runs first, so cached data is never shown to someone who can't see the job.
Pre-load on login/api/me starts loading the recruiter's jobs and submittals in the background.

Measured after a restart: jobs 347 ms (811 jobs), submittals 78 ms, other list pages 55–75 ms, AI notes ~50–70 ms.

Known limits & to-do

  • Task owner matching by name. JobDiva's job-users rows give a contact id, not the user id, so a task is matched to the logged-in recruiter by id or name. Two recruiters with the same name would see each other's tasks. A reliable user-id source would fix this.
  • Time zone is an assumption (US Eastern, from your sample). A wrong zone shifts the 120-minute clock by hours.
  • REC_AI name is assumed. The follow-up check looks for TYPENAME exactly REC_AI. This should be confirmed against a real recruiter note.
  • Hourly refresh only covers jobs already opened (it re-syncs the jobs saved in ai-audit.json). It does not scan every job in the account.
  • Old notes create tasks. Any AI note older than 120 minutes with no follow-up gets a task, including notes on jobs that are already closed. A rule such as "skip closed jobs" or "ignore notes older than N days" may be wanted.
  • Sandbox vs main. All JobDiva calls are read-only. Nothing is committed or written to the main instance.
