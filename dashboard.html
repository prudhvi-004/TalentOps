Why jobs weren't loading

Diagnosis

The problem

Logging in showed an empty jobs list for most recruiters, with no error — so it looked broken. It wasn't.

What we found

The app correctly scopes every JobDiva call to the logged-in recruiter's own USERID via JobsListByUser. Most seeded sandbox accounts simply have zero jobs assigned to them in JobDiva — the empty list was accurate, not a bug. We queried JobDiva directly for every seeded user, found which ones actually have jobs, and activated those accounts.

Bulk-activating recruiter accounts

Built

Added a script path to flip seeded users from UNASSIGNED to RECRUITER and active, reusing the app's own recruiter.store.update() — so every existing rule still applies: a user can't be activated if JobDiva itself marks them inactive, and the "at least one active admin" guard still holds.

Fixing slow and failing job loads

Fixed

The problem

Recruiters with 100+ jobs hit two failures: a "Maximum allowed jobId is 100" error from JobDiva, and request storms that tripped JobDiva's rate limit (429), with one case taking over four minutes to load.

What we changed

  • Chunked the JobsContacts / JobsInternalUsersDetail calls into batches of 50, matching the limit JobsDetail already respected.
  • Added a 60-second in-memory cache for a recruiter's job list, so repeat page loads don't re-hit JobDiva.
  • Added automatic retry with backoff on 429 responses.
  • Capped the job-activity timeline to the most recent 30 two-week windows, so an old job doesn't trigger hundreds of API calls just to render its history.

Interviews, Starts, FPS & My Primary Jobs

Built

Four more dashboard drill-downs, all derived from the same Submittals data already fetched — so none of them cost an extra JobDiva API call:

  • Interviews — submittals with an interview date set.
  • Starts — submittals with a start date, with status worked out from start/end/termination dates (Active, Ended, Unapproved) plus a "Filter Candidates" row (Active / On Bench / Ending in 30 Days / Unapproved).
  • FPS (First Presentation Success) — the earliest submittal per candidate+job pair, since JobDiva has no separate "first presentation" field of its own.
  • My Primary Jobs — submittals where the recruiter is JobDiva's own PRIMARYRECRUITERID on that record.

Fixing the "today" filter showing future dates

Fixed

The problem

With "Today" selected, a record dated weeks into the future (a scheduled interview, a future placement start) still showed up — because the filter only checked date ≥ start of today, with no upper bound.

The fix

Added an upper bound — date < start of tomorrow — to Today, This Week and This Month, so each is a proper trailing window ending now, not open-ended into the future. Verified against synthetic dates at every boundary (today, 6/8/29/31 days ago, and several future dates) before and after the fix.

Progress bars that actually move

Fixed

The problem

Two bugs: the progress bar under each tile was drawn once from old placeholder numbers and never recalculated once real data loaded, and the "Target" number was a fixed value regardless of whether Today, This Week or This Month was selected.

The fix

Each tile's bar and target now update together, every time data loads or the range changes. Targets scale with the range (e.g. Submittals: 1 / 6 / 24 for Today / Week / Month). Selecting Custom Date hides the target and bar entirely — there's no sensible fixed target for an arbitrary date range, so it just shows the count.

Priority shows JobDiva's own value — and salary moved out

Fixed

Job priority used to be translated into a word ("MEDIUM") based on a guess, including defaulting empty values to "medium" — which is how one job with no priority set in JobDiva ended up misleadingly labeled. Priority now displays exactly what JobDiva sends (a raw code like 1 or C, or a dash if JobDiva has nothing set), with no color applied to it anywhere in the app. The Salary row was removed from the job detail view; Bill Rate and Pay Rate already cover that ground.

Job title links out to JobDiva

Built

On the job detail page only, the job title is now a link to that exact job's record in JobDiva's own web console, opening in a new tab. It reads as plain text at rest and turns the app's accent blue with an underline on hover, so it doesn't look like a link until you reach for it. Every other place a job title appears — the Jobs list, the dashboard's Recent Jobs — stays untouched.

Grid to list, by scroll position

Built

For recruiters with more than 12 jobs, the Jobs page starts as a grid of cards. Scroll past where the 12th card ends, and the whole list switches to a compact row view — a colored strip per row matching the job's status, then title, client, location, status, priority, recruiter, and posted date. Scroll back up past that same point and it switches back to the grid. A small buffer zone stops it flickering right at the boundary.
